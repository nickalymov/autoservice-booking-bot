# Пилотный Telegram-бот внутренней записи автосервиса

Автоматизированная система управления расписанием цеха, бронированием рабочих постов и контролем занятости мастеров с поддержкой голосового ввода (Whisper STT), интеллектуального структурирования данных (GPT-4o-mini) и облачной синхронизации с Google Calendar.

---

## 1. Архитектура и стек технологий

Система спроектирована для работы в условиях автосервиса без отдельного приемщика: мастера принимают звонки и клиентов самостоятельно, взаимодействуя с ботом голосом через Telegram одной рукой («масляными руками»), а магазин и владелец контролируют и корректируют общую загрузку в реальном времени.

* **Язык и среда:** Python 3.12, асинхронный рантайм `asyncio`.
* **Фреймворк бота:** Aiogram 3 (роутеры, фильтры, Finite State Machine).
* **База данных:** PostgreSQL 16 (асинхронное ядро SQLAlchemy 2.0 + asyncpg).
* **Искусственный интеллект (шлюз VseGPT):**
  * `stt-openai/whisper-1` — транскрибация голосовых сообщений на русском языке.
  * `openai/gpt-4o-mini` — извлечение сущностей через строгий механизм Structured Outputs (JSON Schema).
* **Интеграция с расписанием:** Google Calendar API v3 (синхронизация событий с календарями каждого поста и выводом на телевизор в ремзоне).
* **Фоновые задачи:** APScheduler (проверка предстоящих нарядов и рассылка напоминаний мастерам за 30 минут).
* **Инфраструктура:** Docker, Docker Compose, SQLite (aiosqlite) для запуска изолированных тестов.

## 2. Быстрый старт и развертывание

### Развертывание через Docker Compose (рекомендуемый способ)

1. Клонируйте репозиторий с проектом:
```bash
git clone <url-репозитория>
cd autoservice-booking-bot
```

2. Создайте файл конфигурации окружения на основе примера:
```bash
cp .env.example .env
```

3. Заполните переменные в `.env` (токен Telegram-бота, ключ VseGPT, ID доверенных пользователей и календарей).

4. Поместите сервисный ключ Google API `credentials.json` в корневой каталог проекта.

5. Запустите стек сервисов:
```bash
docker compose up -d --build
```

6. Просмотр логов работы бота в реальном времени:
```bash
docker compose logs -f bot
```

7. Перезапуск бота при обновлении конфигурации:
```bash
docker compose restart bot
```

8. Остановка сервисов:
```bash
docker compose down
```

## 3. Настройка Google Calendar и вывод расписания на экран

### Подключение Google Calendar API

1. Перейдите в Google Cloud Console и создайте новый проект.
2. В разделе **APIs & Services -> Library** включите **Google Calendar API**.
3. В разделе **Credentials** нажмите **Create Credentials -> Service Account**.
4. Создайте сервисный аккаунт и сгенерируйте для него приватный ключ в формате **JSON**.
5. Скачайте файл ключа, переименуйте его в `credentials.json` и скопируйте в корень проекта.
6. В Google Календаре создайте 5 календарей:
   * **Пост 1 — обычная яма** (код `P1`)
   * **Пост 2 — подъемник 1** (код `P2`)
   * **Пост 3 — подъемник 2** (код `P3`)
   * **Пост 4 — яма / сход-развал** (код `P4`)
   * **Автосервис — Обзорная загрузка**
7. В настройках каждого календаря в разделе **«Доступ для отдельных пользователей»** добавьте email созданного сервисного аккаунта с правом: **«Внесение изменений в мероприятия»**.
8. Скопируйте идентификаторы созданных календарей из их настроек и укажите в `.env` (`GOOGLE_CALENDAR_P1_ID`, `GOOGLE_CALENDAR_P2_ID` и т.д.).

### Вывод расписания на телевизор в ремзоне

Вместо маркерной доски в цехе используется телевизор, подключенный к мини-ПК или Android TV приставке:
1. В веб-версии Google Calendar авторизуйтесь под служебным Google-аккаунтом автосервиса, которому доступны все календари постов.
2. Отметьте галочками отображение всех постов (P1–P4) одновременно: каждому посту присвоен свой цвет.
3. Переключите режим отображения на **«День»** или **«Расписание»**.
4. Запустите браузер на телевизоре в полноэкранном режиме (F11 / Режим киоска).
5. При подтверждении или изменении наряда в боте слот обновляется на экране автоматически в течение нескольких секунд.

## 4. Руководство пользователя (Мастера и Продавцы)

### Ролевая модель доступа

* **Владелец (`OWNER`):** полный доступ, принудительные изменения любых записей, аудит истории, добавление сотрудников в белый список.
* **Мастера Вова, Коля, Рамазан (`MECHANIC`):** создание и правка собственных записей, смена статусов своих нарядов, инициация передачи наряда коллеге, просмотр общей загрузки.
* **Продавцы магазина (`SALES`):** полный доступ к созданию, переносу, отмене и правке любых записей на любые посты, просмотр расписания.

### Сценарии работы

#### 1. Создание записи голосом
Мастер нажимает кнопку записи голосового сообщения и надиктовывает в свободной форме:
> *«Запиши Киа Рио завтра на 10:00, телефон 928 123 45 67, замена стоек стабилизатора, пост 2»*

* Бот транскрибирует аудио, выводит расшифровку в чат и анализирует поля.
* Если пост не назван — бот показывает только свободные посты на это время и вариант «Без поста».
* Если длительность не названа — ИИ и модуль оценки предлагают время, кратное 30 минутам.
* Бот формирует карточку черновика с кнопками: **[Подтвердить]**, **[Изменить]**, **[Отменить]**.
* После нажатия **«Подтвердить»** запись одновременно сохраняется в базе данных и публикуется в календаре соответствующего поста.

#### 2. Взятие автомобиля в работу
При заезде автомобиля мастер нажимает кнопку **«В работу»**:
* Статус меняется на `IN_PROGRESS`.
* Фиксируется точное фактическое время начала.
* Кнопка меняется на **«Завершить»**.

#### 3. Досрочное завершение и освобождение поста
Когда работы закончены, мастер нажимает кнопку **«Завершить»**:
* Если работа закончена раньше планового времени (например, в 11:10 вместо 12:00), бот спрашивает:
  *«Запись была запланирована до 12:00. Освободить P2 с 11:10?»*
* При нажатии **«Да, освободить»**: бронь поста усекается, слот освобождается в календаре цеха и становится доступен для записи другим мастерам.
* При нажатии **«Нет, оставить»**: пост остается забронированным до планового времени.

#### 4. Передача записи коллеге
Мастер может передать свой наряд другому мастеру:
1. Нажимает кнопку **«Передать»**.
2. Выбирает коллегу из списка (Вова, Коля, Рамазан).
3. Запись переходит в статус ожидания передачи, бронь поста сохраняется.
4. Принимающий мастер получает личное сообщение в Telegram с описанием работ и кнопками: **[Принять]** и **[Отклонить]**.
5. При согласии ответственность переходит новому мастеру, оба получают подтверждение.

#### 5. Отмена записи
Если клиент не приехал, сотрудник нажимает **«Отмена»**: запись отменяется, бронь снимается, событие удаляется из календаря.

#### 6. Просмотр загрузки и вечерняя сводка
* Кнопки меню: **«Загрузка сегодня»**, **«Загрузка завтра»**, **«Свободные окна»**, **«Мои записи»**.
* Команда `/summary` выводит вечерний срез: незакрытые наряды за день, план на завтра и перечень свободных окон.

## 5. Регламент аварийного режима (Disaster Recovery)

1. **Если Telegram временно недоступен:**
   * Продавцы магазина открывают веб-интерфейс Google Calendar и продолжают вести записи вручную в сетке постов.
   * Мастера ориентируются по телевизору в цехе, где отображается календарь.
   * После восстановления Telegram мастера актуализируют наряды.

2. **Если Google Calendar временно недоступен:**
   * Бот не рапортует об успешной записи, а сообщает об ошибке интеграции.
   * Черновик сохраняется в базе данных, предотвращая рассинхронизацию между БД и календарем.

## 6. Структура базы данных

База данных построена на 4 нормализованных таблицах:
* `users` — справочник сотрудников, роли (`OWNER`, `MECHANIC`, `SALES`), флаг активности, настройки напоминаний.
* `posts` — справочник рабочих мощностей (`P1`, `P2`, `P3`, `P4`, `NO_POST`), типы постов, привязка к календарям.
* `appointments` — записи на ремонт, публичный ID (`B260910001`), плановые и фактические временные метки, марка авто, телефон, VIN, структурированные операции `work_items`, статус жизненного цикла, внешний `google_calendar_event_id`.
* `history_logs` — журнал аудита всех действий с фиксацией автора, типа действия (`CREATED`, `STATUS_CHANGED`, `TRANSFER_ACCEPTED`, `CANCELLED`), старых и новых значений.

### Задел на будущее (Масштабирование)
* Поля `work_items`, `actual_duration_minutes` и `master_comment` накапливают точные исторические данные по фактической длительности работ для последующего подключения RAG (поиска по базе выполненных нарядов).
* Архитектура ядра (`BookingService`) отделена от Telegram-слоя, что позволяет подключить прямой обмен с 1С:Альфа-Авто, корпоративный мессенджер MAX или клиентский виджет без переписывания логики постов и коллизий.
